# ИУ3 для Android

Приложение кафедры «Информационные системы и телекоммуникации» МГТУ им. Н. Э. Баумана. Android-перенос [iu3-ios](https://github.com/AlMorpheus/iu3-ios) на Kotlin и Jetpack Compose.

## Модули

- `app` — точка входа, создание зависимостей и сборка графа Navigation 3.
- `core:model` — типизированные модели, учебный календарь и планирование напоминаний.
- `core:common` — Clock, dispatchers и scope приложения для DI.
- `core:data-api` — интерфейсы репозиториев и состояние каталога.
- `core:data` — внутренние реализации репозиториев, источники stub-ответов, дисковый кеш, DataStore и фото.
- `core:notifications` — Android-уведомления, AlarmManager, WorkManager и восстановление очереди.
- `core:designsystem` — тема ИУ3, изображения, карточки, общие элементы и фотогалерея.
- `core:navigation` — сериализуемые ключи экранов.
- `features/*` — онбординг, главная, расписание, кафедра, преподаватели, курсы и учебные планы, доска почёта, поступление, выпускники, поиск и профиль.

Feature-модули зависят от `core`, переходы передают наружу через callbacks. Между feature-модулями нет зависимостей. Экраны получают готовые модели; чтение файлов и декодирование JSON находятся в `core:data`.

## Данные

`StubCatalogDataSource` читает ответы из `core/data/src/main/assets/responses`. Hilt передаёт его в `DefaultCatalogRepository` через контракт источника; UI и фоновые задачи используют публичные интерфейсы репозиториев из `core:data-api`. Для подключения сервера меняется binding источника в `DataModule`. Репозитории не извлекаются из Context.

Feature-модули владеют своими ViewModel и подготовкой UI state. Корневая `AppViewModel` обслуживает загрузку приложения и выбор между онбордингом и основной навигацией. Обоснования границ, владельцев состояния и DI приведены в [архитектуре](docs/architecture.md).

Девять JSON-файлов кафедры перенесены из iOS без изменения содержимого. Проекты, программы поступления, доска почёта, развёрнутые карточки преподавателей и рамки лиц извлечены из Swift-данных в JSON. Изображения находятся в `core/designsystem/src/main/assets/images`.

Афиша дополнена локальным снимком 26 публичных ответов bmstu.ru от 8 ноября 2026 года, включая описания и ссылки на исходные изображения. Источник и дата снимка указаны в `events_provenance.json`. Приложение читает снимок из assets.

В исходном checkout новости загружаются из VK; готового мока новостей в нём нет. `news.json` содержит пустой ответ, интерфейс показывает пустое состояние. Сеть для получения каталогов и токены не используются. Coil может загружать изображения по HTTPS из исходных данных.

Профиль, роль, группа, история поиска и настройки уведомлений хранятся локально в DataStore. Фото уменьшается до 512 px по большей стороне и сохраняется в закрытом каталоге приложения. Резервное копирование данных профиля отключено.

## Навигация и Android-адаптации

Navigation 3 сохраняет текущий экран и его состояние при смене конфигурации и восстановлении процесса. Нажатие вкладки открывает её корень и закрывает вложенные экраны; повторное нажатие поиска также фокусирует поле. В аргументах находятся идентификаторы, сами данные берутся из репозитория. У экземпляров экранов отдельные ключи: переход «курс → преподаватель → тот же курс» не смешивает их состояние.

Набор вкладок зависит от роли. На узком экране используется плавающая панель вкладок, на широком — боковая. Визуальные ориентиры сохранены в [документации дизайна](docs/design-reference.md). Системный Back обслуживает Navigation 3. Внешние HTTPS-ссылки, карты, почта и набор номера открываются Android-приложениями; при отсутствии обработчика ссылку можно скопировать.

Напоминания используют разрешение Android 13+, NotificationChannel и периодический WorkManager. Для напоминаний вовремя пользователь может отдельно разрешить точные будильники в настройках Android; тогда используется `setExactAndAllowWhileIdle`. При отсутствии разрешения остаётся неточный режим с пояснением в интерфейсе. После смены профиля или настроек очередь пересчитывается. Android может откладывать неточные будильники в режиме энергосбережения. Доступ к точным будильникам запрашивается только по нажатию пользователя.

## Сборка

Нужны JDK 17 или новее и Android SDK 37. Проект использует встроенную поддержку Kotlin в AGP 9.

Общие настройки вынесены в convention-плагины `build-logic`. Модуль выбирает шаблон application/library/api/feature и нужные Compose/Hilt/serialization плагины. SDK и Java задаются в `gradle/libs.versions.toml`, межмодульные зависимости — через `projects.*`. Примеры: [настройка Gradle-модулей](docs/build-logic.md).

```shell
./gradlew :app:assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Сверка разделов описана в [таблице соответствия iOS](docs/ios-parity.md), результаты сборки и ручных проверок со скриншотами — в [отчёте](docs/verification.md). Успешная сборка не заменяет проверку всех пользовательских сценариев на устройстве.

## Оформление

Приложение автоматически следует системной светлой или тёмной теме Android. Тёмный режим включается в системных настройках экрана. Фотографии, иллюстрации и синие брендовые блоки сохраняют исходные цвета; фоны, текст, ссылки, поля, карточки и навигация используют соответствующую палитру.
